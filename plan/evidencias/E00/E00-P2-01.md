### Equivalencia multiplataforma para el segundo equipo (macOS / Linux / Windows WSL2)

- **Docker Compose (`Database/docker/verificar.py`):** funciona en cualquier plataforma con Docker Desktop o Docker Engine + Python 3, sin requerir instalación nativa de PostgreSQL, MySQL ni MongoDB.
- **Emuladores Firebase (`Database/tests/verificar_local.py --motores firestore`):** requiere Node 24.12+, Firebase CLI y Java 21+ (`JAVA_HOME` o en `PATH`). Usa proyectos con prefijo `demo-` (`demo-bdii-pediatria`, `demo-bdii-cierre`) y loopback `127.0.0.1`, separados de cualquier proyecto real.
- **Procesos nativos (`Database/tests/verificar_local.py`):** detecta automáticamente rutas de Homebrew en macOS (`/opt/homebrew/opt/*` y `/usr/local/opt/*`) o binarios en `PATH` en Linux/WSL2, aceptando `--postgres-bin` y `--mysql-bin` cuando se instalen en rutas personalizadas.

## Integridad y recuperación

- **Sin bases compartidas ni secretos en Git:** todas las pruebas se ejecutaron con datos sintéticos (`SINTETICO`, `DOCKER-SINTETICO`, proyectos `demo-*`), credenciales aleatorias en carpetas temporales o `.docker/secrets/` ignorado por Git (`0600`), y puertos locales en `127.0.0.1`.
- **Reinicio y persistencia comprobados:** `Database/docker/verificar.py` detiene los contenedores con `docker compose down` conservando volúmenes, vuelve a levantar `postgres`, `mysql` y `mongodb`, reejecuta `mongo-init` y comprueba que los registros sintéticos y cuentas de aplicación persisten sin duplicarse ni restablecerse.
- **Limpieza verificada:** al concluir, `verificar.py` ejecuta `docker compose down --volumes` sobre el proyecto aleatorio `bdii-db-test-*` y comprueba con `docker ps -a` y `docker volume ls` que no queda ningún contenedor ni volumen temporal remanente. `verificar_local.py` detiene `pg_ctl`, `mysqld`, `mongod` y los emuladores Firebase y verifica que el directorio temporal `bdii-test-*` fue eliminado íntegramente.
