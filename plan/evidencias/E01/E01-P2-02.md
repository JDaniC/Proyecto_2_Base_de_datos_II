## Alcance implementado

- **MongoDB (`Backend/src/adaptadores/salida/mongodb`):**
  - Conexión estricta a replica set `rs0` mediante usuario de aplicación `laboratorio_app` y base `laboratorio_clinico`, con rechazo explícito de instancias standalone (`RNF-020`).
  - Unidad de trabajo con sesión por comando y transacción multi-documento (`readConcern: snapshot`, `writeConcern: majority`).
  - Atomicidad garantizada: datos, revisiones, auditoría y operación confirman o revierten juntos (`RNF-016`, `RNF-018`).
  - Repositorio de cuenta (`usuarios`, `roles`, `personal`) que construye `CuentaAutorizada` local verificada.
  - Idempotencia durable: clave determinista, detección de replay, validación de permisos vigentes en cada repetición y manejo de transacciones transitorias/`WriteConflict`.
- **Firestore (`Backend/src/adaptadores/salida/firestore`):**
  - Conexión a proyecto demo y emulador local (`RNF-017`), con validación de destino estricta.
  - Transacción atómica donde toda lectura precede estrictamente a cualquier escritura (`RNF-022`).
  - Validador Zod y límites de tamaño: validación sistemática en cada escritura (`validarDocumento`) y restricción de agregados a 256 KB (`MAX_DOCUMENTO`).
  - Repositorio de cuenta pediátrica (`usuarios`, `roles`, `pediatras`) en el ámbito canónico `CENTRO_MEDICO_PEDIATRICO`.
  - Idempotencia con clave de operación determinista SHA-256 y verificación de autorización en replay.
- **Harness de integración (`run-nosql-uow-integration.mjs`):**
  - Docker Compose efímero para MongoDB replica set y `mongo-init`.
  - Descubrimiento automático de Java Runtime e integración con `firebase emulators:exec`.
  - Limpieza completa y garantizada de contenedores, volúmenes y directorios de secretos temporales.
