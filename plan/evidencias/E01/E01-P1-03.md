## 5. Hallazgos confirmados de seguridad

No se confirmó una vulnerabilidad en las rutas implementadas. La autenticación usa `verifyIdToken(token, true)`; cada petición protegida relee estado/roles/permisos locales, y no consume rol ni institución del body o query. Los fallos de Firebase y persistencia se traducen a errores genéricos.

| ID | Observación | Estado / severidad | Evidencia y acción |
|---|---|---|---|
| S-01 | No se validó el IAM del proyecto Firebase de entrega | BLOCKED / INFO | El único ensayo de Firebase fue Auth Emulator con usuario sintético. Antes de la demostración final, verificar proyecto, claims, revocación y permisos del runtime con una cuenta de ensayo controlada. |
| S-02 | No hay rate limit propio en la API | NEEDS_VALIDATION / INFO | No existe login de contraseña en backend y Firebase verifica el token; no se probó un proxy de entrega ni su throttling. Configurar/verificar límites en la frontera de despliegue antes de exposición pública. |
| S-03 | Carrera de provisión del mismo UID en instituciones diferentes | CONFIRMED en SHA `10501be`; corregido en revisión | Se adquiere advisory lock PostgreSQL por UID, compartido entre procesos; dentro del bloqueo se consultan los cuatro repositorios y se rechaza UID duplicado antes de escribir el claim. Regresión unitaria e integración con sesiones independientes pasan. Inserciones por vías externas al CLI no quedan cubiertas. |
| S-04 | Auth Emulator conectado a proyecto Firestore real | CONFIRMED en SHA `10501be`; corregido en revisión | La composición exige Auth y Firestore emulados juntos con el mismo ID `demo-*`; la regresión verifica que una configuración mixta se rechace antes de abrir motores. |

La revisión Codex también detectó que el repositorio SQL devolvía al pool una conexión si fallaba `ROLLBACK`. `enTransaccion` ahora la descarta y una prueba unitaria verifica `liberar(true)`. La integración PostgreSQL confirma la liberación del advisory lock tras excepción.

Controles revisados: SQL parametrizado; consultas de MongoDB/Firestore con selectores constantes; no hay `eval`/shell ni rutas de archivos desde entrada; errores externos no se devuelven al cliente; los errores del CLI se reducen a códigos/configuración saneados. `npm audit --omit=dev --audit-level=high` terminó con `found 0 vulnerabilities`. Los scripts de triage de seguridad no interpretan TypeScript, así que su salida vacía no se cuenta como veredicto.

## 9. Riesgos residuales

- La guardia común niega operaciones sin permiso vigente, pero cada ruta futura debe autorizar también el recurso concreto y construir respuestas con DTOs de campos permitidos.
- El endpoint de sesión no demuestra persistencia clínica ni reemplaza Firebase Auth en cliente.
- Provisión usa claim Firebase y actualización local en pasos recuperables, no una transacción distribuida. El bloqueo PostgreSQL cubre ejecuciones concurrentes de este CLI; no cubre inserciones iniciales por vías externas ni agrega auditoría con actor verificado.
- En MySQL el esquema de odontología no tiene bandera independiente `odontologo.activo`; la elegibilidad usa cuenta activa y vínculo a fila profesional. La desactivación independiente de perfil necesita decisión/migración explícita si se exige.
- La evidencia de emuladores no certifica IAM, TLS, rate limiting ni restauración de la infraestructura de entrega.
