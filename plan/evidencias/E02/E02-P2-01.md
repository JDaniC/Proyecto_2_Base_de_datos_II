Ejecutor: Davidix888. Fecha: 27/10/2026, America/Guatemala. [PR #42](https://github.com/JDaniC/Proyecto_2_Base_de_datos_II/pull/42), base develop `93b6b30`, dependencias E01 y E02-P1-01 integradas. Estado de revisión/integración: pendiente; esta evidencia no marca la tarea HECHA.

## Resultado implementado

El bundle de laboratorio conecta los casos comunes a MongoDB con una única session por comando. Alta incluye paciente/cabecera embebida, reserva, auditoría y operación durable; actualización usa revisión condicionada, conserva snapshot y aplica solo los campos modificados. Contactos secundarios, sus UUID, segundos nombres/apellidos, fechas ausentes, etiquetas de sexo legadas, cabecera y códigos preexistentes se conservan.

El documento capturado conserva su formato; la reserva y `numero_busqueda` usan la normalización común. Variantes con espacios/guiones no duplican pacientes. La búsqueda aplica prefijos de palabras normalizados, índices específicos, proyección explícita y cursor vinculado a filtros/orden con clave `(fecha_registro, UUID)`. Los adaptadores no devuelven documentos BSON completos a la UI.

La UoW revalida cuenta/roles/versión en la session antes de una escritura y al recuperar resultados previos; reconcilia commit incierto con la misma clave. Duplicados de identidad se traducen a PACIENTE_DUPLICADO sin mostrar el error físico. Revisiones superiores a int32 se escriben como BSON Long; desbordamiento del entero seguro revierte el comando.

## Compatibilidad física y migración

Inicializador ampliado con `claves_nombre`, `numero_busqueda` y dos índices; no modifica volúmenes existentes. `Database/migrations/003_pacientes_busqueda_mongodb.js` proporciona preflight, backfill transaccional, reejecución y recuperación. Requiere cuenta administrativa, respaldo y escritores detenidos, según `Database/migrations/README.md`. No cambia datos clínicos para completar campos desconocidos.

La migración rechaza duplicados normalizados/reservas incompatibles antes de alterar documentos. La prueba provoca un índice único defectuoso, demuestra rollback de todo el backfill, retira únicamente ese índice de fallo y reanuda sin borrar datos. El inicializador actualizado se vuelve a ejecutar sobre la base migrada sin deriva. Los índices previos ajenos se conservan.

Lecturas comunes de fecha/sexo se amplían a null y sexo legado a texto, conforme a DEC16/AF01/OpenAPI. Captura nueva conserva sus validaciones estrictas. Es necesario para MongoDB aunque el PR SQL #41 siga abierto. No se copió código de su rama ni se implementó SQL. Los cambios comunes de composición se limitan a laboratorio; los tipos deberán conservar esta semántica al integrar ambos PR.

## Hallazgos resueltos durante la ejecución

- La comprobación de collMod se ajustó a la API disponible de mongosh; el backfill usa start/commit/abort explícitos para no reintentar indefinidamente un fallo administrativo provocado.
- La prueba de reinicio reprodujo pérdida del formato de identificación; se corrigió almacenando el valor capturado y reservando su clave canónica aparte.
- Pruebas HTTP ejecutadas en la sandbox restringida devolvieron EACCES en loopback. La ejecución final con permisos de puertos locales pasó completa; no se alteraron criterios ni se omitieron esos tests.
