# E02-P1-03 — integración de pacientes en React

Fecha: 28/10/2026, America/Guatemala. Ejecutor: JDaniC. Rama `codex/e02-p1-03-pacientes-react`, [PR #47](https://github.com/JDaniC/Proyecto_2_Base_de_datos_II/pull/47).

## Resumen de auditoría funcional

Skills aplicadas: `functional-requirements-auditor` y revisión dirigida de sesión/aislamiento con `security-auditor`. Alcance: frontera HTTP de pacientes, composición, formularios, búsqueda y proyección paginada del expediente. Se revisaron las fuentes RF/RNF, DEC06–10/16–17, tarea, OpenAPI, controladores, DTO y persistencias ya integradas antes de diseñar pruebas. No se audita aquí toda la clínica E03–E05.

El modo API usa el cliente compartido con autenticación; la institución y permisos proceden de la sesión del servidor. Alta, edición, búsqueda y expediente usan `/api/v1/pacientes`. La ficha administrativa no solicita historial y la ficha clínica representa solo la proyección recibida. Los formularios conservan la misma intención UUID ante respuesta incierta; edición envía solo campos cambiados y versión. La respuesta incierta bloquea cambios de datos hasta confirmar el reintento.

## Inventario real y contratos

No se considera limpia la revisión original; se requiere otra revisión nativa del nuevo SHA.

## Tercera pasada de auditoría

Codex identificó en `33e509d` que la firma de intención contenía un identificador temporal del responsable nuevo. El formulario ahora calcula la firma a partir del mismo mapper puro usado por HTTP (alta o PATCH), excluyendo metadatos visuales. Alta API ya no genera IDs temporales del adulto. Se añadió regresión específica con tiempo entre envíos y pérdida de respuesta real después del commit pediátrico. La operación original se reconcilia con la misma clave. Se requiere nueva revisión nativa del commit corregido; no se reutiliza el veredicto anterior.

Pérdida de respuesta después del commit verificada tanto en hospital como en alta pediátrica con adulto nuevo; clave/cuerpo estables y operación original confirmada. AF10 corregido; cero desviaciones funcionales abiertas en esta pasada.
